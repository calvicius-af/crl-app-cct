Aprender Docling · Lição 02

Ler a estrutura, não o texto

Listar as cláusulas de uma convenção sem escrever uma única expressão regular.

Porque é que isto interessa

Esta é a lição que a missão pede. O cct/extractor.py tem RE_CAPITULO, RE_SECCAO, RE_ANEXO, RE_CLAUSULA, RE_ARTIGO e mais meia dúzia de regras para deduzir a hierarquia a partir de texto plano. O Docling entrega-a já feita. Vais ver a mesma informação, obtida de outra maneira.

1. O documento é uma árvore, não uma string

O DoclingDocument tem duas famílias de campos:

CampoO que guarda
texts, tables, picturesOs itens de conteúdo — listas planas de tudo o que existe no documento
body, groupsA árvore: quem é filho de quem, e em que ordem se lê
furnitureO que não é conteúdo: cabeçalhos e rodapés de página
pagesAs páginas de origem

Repara no furniture. O teu extractor tem um RE_RODAPE_BTE para apagar as linhas BTE 2 | 2025. O Docling separa o mobiliário do conteúdo por construção — não é uma regra tua, é uma decisão do modelo de layout.

Cada item tem rótulo e proveniência

Todo o item de conteúdo traz um label — um valor de DocItemLabel — e uma lista prov com a sua proveniência. Os rótulos que te interessam nas convenções:

DocItemLabelO que costuma ser numa convenção
TITLEO título do contrato coletivo
SECTION_HEADERCAPÍTULO I, Cláusula 1.ª, ANEXO II
TEXTO corpo dos números da cláusula
LIST_ITEMAs alíneas — a), b), c)
TABLEA tabela salarial do anexo
PAGE_FOOTERBTE 2 | 2025 — vai para a furniture

E a proveniência de cada item tem três campos: page_no, bbox (a caixa na página) e charspan. Guarda o charspan: o teu doc.json vive de char_start e char_end, e é por aqui que a rastreabilidade sobrevive a uma eventual troca de extrator. Confirma empiricamente a que texto é que esse intervalo se refere antes de construir alguma coisa em cima dele — é a experiência número um da tua lista.

2. O código

O script completo está em exemplos/listar_clausulas.py. O coração são estas linhas:

from docling.datamodel.base_models import InputFormat
from docling.datamodel.pipeline_options import PdfPipelineOptions
from docling.document_converter import DocumentConverter, PdfFormatOption
from docling_core.types.doc import DocItemLabel

opcoes = PdfPipelineOptions(do_ocr=False, do_table_structure=True)
conversor = DocumentConverter(
    format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=opcoes)}
)
doc = conversor.convert("convencao.pdf").document

# a ordem de leitura é a ordem em que iterate_items devolve os itens
for item, nivel in doc.iterate_items():
    if getattr(item, "label", None) is DocItemLabel.SECTION_HEADER:
        pagina = item.prov[0].page_no if item.prov else "?"
        print(f"p.{pagina}  {'  ' * nivel}§ {item.text}")
A armadilha da configuração

As chaves de format_options têm de ser membros do enum InputFormat, com o FormatOption correspondente por valor. Escrever {"pdf": PdfPipelineOptions(...)} não dá erro de tipo — rebenta em execução com AttributeError: 'PdfPipelineOptions' object has no attribute 'backend'. Duas camadas: PdfFormatOption por fora, PdfPipelineOptions por dentro.

Os valores por omissão, verificados

Estes são os valores de PdfPipelineOptions() na versão 2.121.0, lidos do pacote instalado — não são o que a documentação diz, são o que o código faz:

OpçãoPor omissãoPara as convenções
do_ocrTruePõe False: os PDFs do BTE são digitais
do_table_structureTrueDeixa: são as tabelas salariais
table_structure_options.modeACCURATEDeixa. FAST só para explorar
table_structure_options.do_cell_matchingTrueSe as colunas da tabela salarial saírem fundidas, experimenta False
artifacts_pathNoneObrigatório no CRL — lição 03

3. As tabelas, que é onde está o dinheiro

Literalmente. As tabelas salariais são o conteúdo que o teu extractor hoje trata pior — delimita-as com sentinelas e devolve-as como texto. Aqui saem estruturadas:

for tabela in doc.tables:
    df = tabela.export_to_dataframe(doc=doc)   # pandas.DataFrame
    print(tabela.data.num_rows, "x", tabela.data.num_cols)
    df.to_csv("tabela.csv", index=False)
Pergunta em aberto — experiência para fazeres

Uma tabela salarial que atravessa três páginas sai como um TableItem ou como três? Não encontrei fonte que responda, e para o teu corpus isto decide muita coisa. Corre e conta. Seja qual for a resposta, é registo de aprendizagem — e talvez uma discussão a abrir no repositório do Docling.

5. O teu ganho

Guarda isto

Listaste a hierarquia de uma convenção sem uma regex, e sabes onde ir buscar a página e o intervalo de caracteres de cada item. Compara a tua listagem com a saída do cct/extractor.py no mesmo PDF: onde é que os dois discordam? Essa lista de discordâncias é a matéria-prima da decisão técnica que fecha a missão.
