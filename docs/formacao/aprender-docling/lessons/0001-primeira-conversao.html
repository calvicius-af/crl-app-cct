Aprender Docling · Lição 01

A primeira conversão

Um PDF do BTE entra; um documento com estrutura sai. Vinte minutos.

Porque é que isto interessa

O cct/extractor.py recebe do pdfplumber um rio de texto e tem de adivinhar, à regex, onde começa cada cláusula. O Docling faz a segmentação antes de te entregar o documento. Esta lição é o momento em que vês essa diferença com os teus olhos, num PDF teu. Ver MISSION.md.

1. O que o Docling é (e o que não é)

O Docling não é uma biblioteca de leitura de PDF como o pdfplumber ou o PyMuPDF. Essas dão-te o que está fisicamente escrito na página: caracteres, coordenadas, palavras. O Docling usa uma dessas por baixo — chama-lhe backend — e depois passa cada página por um modelo de layout treinado para reconhecer o papel de cada bloco: isto é um título de secção, isto é um parágrafo, isto é um item de lista, isto é uma tabela, isto é o rodapé da página.

O resultado é um DoclingDocument: uma estrutura em árvore, com ordem de leitura, onde cada item tem um rótulo (label) e sabe de que página veio. Podes exportá-lo para Markdown (legível) ou para JSON (completo, sem perdas).

PeçaO que fazNo teu vocabulário
backendLê os bytes do PDF e devolve células de texto com coordenadaso papel que o pdfplumber faz hoje
pipelineOrquestra: layout → OCR (se preciso) → tabelas → montagema Fase 1 do AppCCT
DoclingDocumentO documento com hierarquia, rótulos e proveniênciao teu doc.json, mas produzido por modelo em vez de regex

Conta com isto

Um ambiente virtual limpo com o docling ocupou 5,5 GB quando esta lição foi escrita — o pacote arrasta o PyTorch. As quatro dependências actuais do AppCCT ocupam uns 30 MB. Instala num ambiente virtual à parte, nunca no .venv do projeto: enquanto não houver decisão tomada, o Docling não é dependência do AppCCT, é uma ferramenta em cima da mesa.

E a primeira conversão vai à internet buscar os modelos. Nas máquinas do CRL isso não acontece — é o assunto inteiro da lição 03. Nesta lição usa a tua máquina de desenvolvimento.

3. A primeira conversão

Escolhe um PDF do BTE que já conheças bem — o do exemplo ACIP/FESAHT serve, e conheces o resultado que o extractor actual dá. A linha de comandos chega:

.venv-docling/bin/docling CAMINHO/PARA/O/TEU.pdf \
    --to md --to json --output ./saida-docling/
"does not exist" — antes de tudo, onde está o terminal?

O docling não procura o PDF em pasta nenhuma especial: o primeiro argumento é um caminho de ficheiro, lido a partir da pasta onde o terminal está nesse momento. Se escreveres só o nome do ficheiro (docling convencao.pdf), isso significa "o ficheiro chamado convencao.pdf na pasta actual" — e se a pasta actual for outra, ou o nome não bater certo (maiúsculas, espaços, 3_BTE_2_… em vez de 25_PR_003_BTE_02_…), dá exactamente este erro.

Três passos para sair disto, por ordem:

  1. pwd — mostra onde o terminal está agora.
  2. ls — mostra o que há nessa pasta. O PDF aparece na lista? Se não, o terminal está na pasta errada ou o PDF está noutro lado.
  3. Em vez de adivinhar o caminho, arrasta o ficheiro do Finder para dentro da janela do Terminal, depois do comando — o macOS escreve o caminho completo e correcto por ti, com aspas incluídas se houver espaços no nome.

Fica com o hábito de confirmar sempre com ls antes de correr o docling a sério — é mais rápido do que decifrar o erro depois.

Da primeira vez demora: descarrega os modelos e converte página a página, em CPU. Ficas com um .md e um .json de nome igual ao PDF, dentro de saida-docling/.

Três flags que vais querer já:

FlagEfeitoQuando
--no-ocrDesliga o OCROs PDFs do BTE são de origem digital: o texto já lá está. Poupa muito tempo.
--page-range 1-4Converte só essas páginasPara experimentar. Uma convenção de 60 páginas em CPU é uma pausa para café.
--table-mode fastTableFormer rápido em vez de exactoQuando estás a explorar. Para as tabelas salariais a sério, deixa o valor por omissão (accurate).

4. Olha para o que saiu

Abre o Markdown. Não o leias como texto — lê-o como estrutura. Procura três coisas, por esta ordem:

  1. As cláusulas viraram cabeçalhos? Se Cláusula 1.ª aparece como ## Cláusula 1.ª, o modelo de layout reconheceu-a como título. Isso é a informação que o teu RE_CLAUSULA hoje tem de arrancar do texto plano.
  2. As duas colunas ficaram na ordem certa? Este é o teste duro dos PDFs do BTE. Confirma que o fim da coluna esquerda liga ao topo da coluna direita, e não a meio de uma frase da página seguinte.
  3. A tabela salarial do anexo é uma tabela? Se vier em sintaxe de tabela Markdown com linhas e colunas, o Docling reconheceu-a. Hoje o teu extractor delimita tabelas com sentinelas (MARCA_TABELA_INI) e trata-as como texto.
Sinais de que correu mal

Output quase vazio, ou cheio de �: o PDF é digitalizado — tira o --no-ocr. A mesma linha repetida muitas vezes: problema de layout, e a resposta do projeto é o pipeline VLM, que exige GPU e está fora da tua missão. Se um PDF do BTE fizer isto, é achado a registar, não a contornar.

6. O teu ganho

Guarda isto
